# Cattle correction and exit workflows

Bulk Edit is administrator-only at both the HTTP route and transactional service. It selects current active animals on the selected PIC, and updates only explicitly checked fields. Clearing an optional selected field is intentional; unchecked fields retain their values. An empty purchase cost means unknown, and does not imply a zero-price acquisition. Preview displays the exact animals and changes; save is atomic under the existing property lock with a permanent submission key and audit event.

Edit Animal uses the Cattle Entry grid and controls, with date-only Farm Entry Date, typed or previously recorded breed/description, eligible PIC mobs, and a signed confirmation. Identifier permissions use current saved identifiers inside the transaction. Standard users can fill an empty identifier, but cannot replace or clear a populated one. Source PIC and NVD changes require an administrator. The dedicated historical Replace ear tag workflow retains its previously authorised role rules. Identifiers remain globally and permanently reserved even after correction or reversal.

Corrections append per-animal metadata and before snapshots to the event ledger. Original acquisition events are not rewritten. Purchase corrections post a delta against the acquisition's existing presence cycle, resolve unknown allocations, and never create a second purchase. A transfer's occupancy links back to its acquisition cycle for later price correction. Historical timestamp-based correction services remain available and retain their original cycle selection. Correcting a current entry date affects the current open presence and its arrival-aligned open membership only; conflicting prior presence or historical animal activity is rejected. Corrections can be reversed through the existing audited administrator correction route once downstream dependencies are resolved.

## Calendar dates and age

An unchanged entry calendar date retains its saved timestamp, including existing imports and transfers. A changed Farm Entry Date retains the documented local-midnight convention: ISO date converted to 00:00:00 using the property's IANA timezone and `clock.local_timestamp`. Future dates, overlapping periods and DOB after farm entry are rejected.

Farm Exit Date represents departure after that calendar day's recorded activity. For a past day, conversion uses the next property's local midnight minus one second. For today, it uses the preparation timestamp. The prepared timestamp is signed with the preview and preserved on save; the service checks that it still belongs to the chosen property-local date and is not in the future. Computing boundaries in local calendar time, rather than adding 86,400 seconds, preserves the selected date over 23/25-hour DST days. Ambiguous or nonexistent midnight is rejected by the existing timezone validator. Timestamp-based historical service callers retain their timestamp convention. The selected property's current date supplies the form default; standard users may backdate exits, subject to chronology and access checks.

Age uses DOB first, otherwise reference entry date **minus** estimated weeks, otherwise the existing labelled farm-entry fallback in Active Cattle. Homepage unknown-age grouping is unchanged. Repurchase and transfer retain the original estimate/reference. Leaving the estimate unchanged in Edit Animal retains that reference; intentionally changing it anchors the new estimate to the current Farm Entry Date. Re-dating the arrival to which an estimate was originally anchored adjusts that reference, without reinterpreting an earlier estimate at a later repurchase.

## Sale, transfer and death

Sale and Transfer support a whole mob or a searchable individual list with removal and duplicate prevention. A whole-mob preview shows the exact animals before confirmation. A property version check and exact participant snapshot prevent silently including changed membership. Selection, dates, active presence and access are rechecked in the same transaction that saves the batch. Price mode is Per Head or Group Total; existing fixed-precision deterministic allocation preserves totals exactly.

Sale preview displays warnings using the greatest applicable underlying restriction end date, excluding reversed and superseded treatments. It uses the prepared exit instant, never the Active Cattle value clamped to today. Explicit acceptance remains required under the existing departure rule; changes after preview require refreshed review. Sale closes presence, marks exited, posts revenue, and permits a later valid repurchase of the same permanent identity.

Transfer requires another PIC on the same authorised property. It atomically closes source occupancy and memberships, opens destination occupancy, updates the animal's current PIC, and writes linked source `transfer` and destination `transfer_arrival` events/participants. Identity, age reference, restrictions and financial history remain attached to the animal. There is no sale revenue, new purchase or inherited source mob. Historical reports use frozen presence PICs. Ordinary transfer reversal is deliberately unavailable through simple reversal; it requires a separately reviewed historical correction workflow to avoid overlapping downstream occupancy.

Death records the reason/date, closes presence and memberships, and marks dead without sale revenue. Repurchase, Purchase, Birth and purchase-only imports cannot bypass that status or reuse the reserved identity. The existing administrator-only audited death reversal remains available subject to downstream dependency checks.

Previews expire after 30 minutes and are bound to the account, operation, source context generation, exact input and property version. Retrying an identical confirmed save returns the existing result. Validation failures retain submitted input. Mode switching retains shared and mode-specific values in tab-local session storage, keyed by account and signed property/PIC context. No database draft is created.

## Shared identifier validation and legacy records

`herd/identifiers.py` validates entire strings using ASCII patterns: PIC `0XXXX000`, visual `0XXXX000XXX00000`, RFID 15 digits, NVD 8 digits. It trims surrounding whitespace, uppercases letter-bearing identifiers, rejects internal spaces/punctuation/non-ASCII digits, and preserves leading zeros. Mother identification accepts visual or RFID and stores its kind in event metadata. Entry, edit, exit, property/PIC forms, tag services and imports share authoritative validation; applicable browser text inputs provide patterns/hints and numeric keyboards. Partial searches continue to use lookup semantics without full-format validation.

Unchanged legacy values remain viewable and do not block unrelated animal edits. They are never rewritten automatically. Changed/new identifiers must pass the new rules in addition to permanent uniqueness and access checks. `manage.py audit_identifiers` provides a read-only count of nonconforming database fields and historical event occurrences, without disclosing identifier values or modifying records.

The supplied `docs/reference/StockLOG_bulk_stock.csv` was scanned: **57 rows; 0 nonconforming supplied visual, RFID, source PIC or NVD values**. Older synthetic tests used invalid placeholders (`TEST0001`, repeated-letter visual IDs, `SRC`, `NVD`); their synthetic fixtures were updated to valid formats. No production/VPS database was opened or scanned, so no claim about live identifier conformity is made.

No schema migration or installer change is required. The Caddy root:caddy 0640 permissions fix and service-user validation checks remain unchanged. No merge, deployment, server reinstall or data wipe is part of this work.
